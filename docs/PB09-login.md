# PB-09 로그인 UI

이슈 #4의 로그인 화면을 Compose로 구현한다. 로그인 API·토큰 보관·인증 복원은 연결 전이다.

## 확인

1. Android Studio에서 app debug를 실행한다.
2. 시작 화면의 `로그인`을 누르면 빈 입력 화면을 연다.
3. `PB-09 로그인 UI 미리보기`에서 입력 전·입력 후·로그인 오류 상태를 선택한다.
4. 미리보기에서 형식이 맞는 이메일과 비밀번호를 제출하면 0.8초 뒤 샘플 인증 오류를 표시한다. 실제 계정을 사용하지 않는다.
5. 비밀번호 보기·가리기, 빈 입력·이메일 형식 오류, 제출 중 중복 클릭 방지, 스크롤과 키보드를 확인한다.

## 구성과 연결

- `LoginScreen`: 상태와 이벤트를 받는 UI. Figma 원본 로고·아이콘과 Pretendard Medium을 사용한다.
- `LoginViewModel`: 입력 검증과 제출 상태를 관리한다. 이메일 앞뒤 공백만 제거하고 비밀번호는 그대로 전달한다.
- `LoginSubmitter`: API 담당자가 구현할 suspend 제출 계약. Success·InvalidCredentials·Unavailable·ConnectionError를 구분한다.
- `LoginRoute`: ViewModel 상태 관찰 및 화면 이동 이벤트를 연결한다.
- `LoginActivity`: 현재 Unavailable 제출기를 사용한다. 실제 인증 성공을 생성하지 않는다.
- 회원가입 버튼은 실제 로그인과 debug 미리보기 양쪽에서 SignUpTermsActivity로 이동한다. 재설정·소셜 버튼은 기능 준비 안내를 표시한다.
- 비밀번호는 ViewModel 메모리에만 두며 SavedStateHandle·SharedPreferences·로그에 저장하지 않는다. 성공 시 지운다.
- 원본 디자인의 로그인 버튼 높이는 27dp이고 필드는 40/43dp이다. 56dp 고정 공통 버튼으로 표현할 수 없어 인증용 레이아웃을 사용한다. clickable의 터치 영역은 Compose가 확장한다.
- 소셜 OAuth, 비밀번호 재설정, 인증 복원에 따른 로그인/홈 분기는 후속 연결 작업이다.
- 폰트 라이선스는 APK의 `assets/licenses/pretendard.txt`에 포함한다.

- 회원가입 3단계 상태·UI 테스트 7개(비밀번호 규칙·일치·보기, 닉네임 길이, 중복 제출, 미연결 API, 완료 후 비밀번호 제거·이동)

전체 인증 기능 완료나 FE–BE 인증 연동 완료를 의미하지 않는다.

## 회원가입 1단계

- 약관 목록은 첨부 디자인의 필수 3개(서비스·개인정보·연령/보호자), 선택 1개(마케팅)를 사용한다. 필수 항목 수는 PM·Design 확정이 필요하다.
- 원본의 `필수 서비스 이용 약관 4종 일괄 동의`는 목록과 맞춰 `필수 3종 및 선택 약관 일괄 동의`로 표시한다.
- 최초 진입은 모두 미동의다. 필수 3개에 동의하면 선택 동의 없이도 다음 버튼을 활성화한다.
- 전체 동의는 선택 약관까지 선택/해제한다. 전문 보기 화살표는 동의 상태를 바꾸지 않는다.
- 상단 뒤로가기와 시스템 뒤로가기는 진입한 로그인 화면으로 복귀한다.
- 선택 상태는 rememberSaveable로 회전·Activity 재생성 시 복원한다.
- 약관 원문은 제공되지 않아 전문 보기에는 준비 안내를 표시한다. 임의 약관은 작성하지 않는다.
- 다음 버튼은 EmailVerificationActivity로 이동한다. 선택 마케팅 동의와 debug UI 테스트 여부를 전달한다.
- 헤더와 다음 버튼은 고정하고 본문을 스크롤해 작은 화면에서도 항목을 확인할 수 있다.

## 회원가입 2단계 이메일 인증

- 약관 필수 동의 후 다음 단계로 이동한다. 뒤로가기는 기존 약관 선택 상태를 유지한다.
- 이메일 형식 검사, 입력 지우기, 숫자 6자리 입력, 번호 불일치 안내, 재발송, 타이머를 제공한다.
- 로그인 미리보기에서 진입할 때만 debug 샘플 Gateway를 사용한다. 실제 이메일 발송은 없다. 샘플 `123456`은 성공, 나머지 번호는 불일치를 반환한다.
- 실제 로그인 진입은 미연결 Gateway를 사용하고 API 준비 안내를 표시한다. 샘플로 인증 성공이나 발송을 가장하지 않는다.
- `EmailVerificationGateway`는 발송 결과의 challengeId·validForSeconds와 인증 결과를 UI에 전달하는 FE 내부 계약이다. BE API 계약을 확정한 것은 아니다.
- UI 샘플은 180초다. 실제 연결에서는 서버가 반환한 유효시간을 사용한다. 타이머는 elapsedRealtime 종료 시각 기준이고 앱 복귀 시 다시 계산한다.
- 이메일 변경·지우기는 기존 번호와 인증 상태를 초기화하고 진행 요청을 취소한다. 이전 요청의 응답은 새 이메일 상태에 반영하지 않는다.
- 재발송 성공 시 기존 번호·오류를 지우고 타이머를 갱신한다. 처리 중에는 중복 발송·확인을 차단한다.
- 시간 만료는 기존 오류 문구 위치에 표시하고 다음 버튼을 비활성화한다. 성공은 같은 화면에 완료 안내를 표시한다. 별도 화면 디자인은 추가하지 않는다.
- 인증 성공 후 SignUpCredentialsActivity로 이동한다. 인증한 이메일, 마케팅 동의, debug 테스트 여부를 전달한다.
- Activity 회전에는 ViewModel을 유지한다. 프로세스 종료 후에는 초기 상태로 재진입해 다시 인증한다. 인증번호·인증 성공 상태를 영구 저장하지 않는다.

## 회원가입 3단계

- 이메일 인증 성공 후 비밀번호·확인·닉네임 설정으로 이동한다. 뒤로가기는 인증 화면으로 복귀한다.
- 비밀번호는 8~20자와 ASCII 영문·숫자 조합을 요구한다. 특수문자는 원본의 보통/높음 강도 표시에 사용하며 필수로 차단하지 않는다. 이 규칙은 UI 디자인 기반 초안이고 PM·BE 확정이 필요하다.
- 길이·조합 조건 만족은 보통, 특수문자까지 있으면 높음으로 표시한다. 비밀번호 두 입력이 실제로 같을 때만 일치 안내를 표시한다. 원본의 서로 다른 예시에 표시된 일치 문구는 재현하지 않는다.
- 닉네임은 공백만 입력한 값을 거부하고 Unicode code point 기준 최대 10자를 검사한다. 초과 입력을 잘라 숨기지 않고 글자 수와 오류를 표시한다. 허용 문자·중복 검사는 BE 정책 확정 후 연결한다.
- 제출 중 중복 클릭·입력 변경을 막는다. 서버 닉네임 중복은 별도 필드 오류로 표시하고 입력 수정 시 해제한다.
- SignUpSubmitter는 FE 내부 제출 계약이다. 실제 가입 API·이메일 인증 증명·토큰 계약은 연결 전이다.
- 샘플 가입 성공은 debug PreviewSignUpSubmitter만 반환한다. 서버 계정이나 토큰을 생성하지 않는다. 실제 진입에서는 API 준비 안내를 표시한다.
- 가입 완료 팝업은 입력 이메일·닉네임을 사용한다. debug에는 실제 가입·보호 활성화가 없다는 표시가 있다.
- 완료 후 비밀번호·확인 입력은 ViewModel에서 지운다. 영구 저장·SavedStateHandle·로그에 남기지 않는다.
- 완료의 홈 버튼은 현재 앱 시작 MainActivity로 복귀하며 인증 화면 back stack을 제거한다. 홈 UI와 프로필·보호자 설정은 연결 전이다.
