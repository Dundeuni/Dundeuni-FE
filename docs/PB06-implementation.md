# PB-06 검사 기록 목록 · 상세 · 빈 상태

## 실행

- 실제 기록: 기존 홈 화면의 **최근 검사 → 전체 기록 보기**.
- 홈의 검사 및 로그인 흐름은 `origin/dev`를 유지합니다. 샘플 화면은 Android Studio의 HistoryPreviewActivity.kt Compose Preview로 확인합니다.
- 목록 우측 상단에서 기본/쉬운 모드 전환.
- 카드 선택 → 상세. 상단 뒤로 버튼이나 시스템 뒤로 가기로 목록 복귀.
- 검색 버튼 → 유형/위험 단계 검색. 필터와 검색은 함께 적용됨.
- 기록 삭제와 전체 삭제는 실제 화면에서 확인창을 거침. 전체 삭제는 필터 결과가 아닌 모든 기록에 적용.

## 구현

- `src/main/.../feature/history`: HistoryActivity, HistoryRoute, HistoryScreen, HistoryRecord, HistoryStore.
- 목록: 최신순, 오늘/어제/날짜별 그룹, 유형별 건수, 위험 단계 배지, 검색, 가로 스크롤 필터.
- 상세: 저장 시각, 유형, 최종 위험 단계, 독립 사기/AI 점수, 근거 누락 안내, 위험 단계별 기본 안내, 개별 삭제.
- 상태: 기록 없음, 필터/검색 결과 없음, 로딩, 로딩/삭제 오류 및 재시도.
- 쉬운 모드: 상단 상태 배지/검사명/시간, 하단 검사 내용/위험 안내/원형 화살표로 카드 배치. 위험 발견은 경고 아이콘과 붉은 안내 사용.
- 검색: TextFieldValue로 한글 조합 상태 유지, 일반 텍스트 입력/검색 IME, 검색창 초점과 화면 키보드 표시, 키보드 영역 패딩 처리.
- 기존 홈의 전체 기록 보기 동작과 main Manifest 내부 Activity 등록. 기존 플로팅 버튼과 PB-05 흐름 유지.
- 별도 debug 샘플/Compose Preview. 샘플은 실제 SharedPreferences에 저장하지 않음.

## 데이터 범위와 후속 연동

PB-05가 사용하는 `analysis_result_history` SharedPreferences의 `results`를 그대로 읽습니다.
기존 `id`, `riskLevel`, `savedAt`, `fraudScore`, `aiScore`는 호환됩니다.
선택적 `type`은 SCREEN/LINK/IMAGE/TEXT를 지원하며, 기존 기록은 유형 정보가 없으므로 **검사**로 표시합니다.
원문, URL, 근거 텍스트를 새로 저장하거나 복원하지 않습니다. 실제 상세 화면은 해당 정보가 저장되지 않았다고 안내합니다.
잘못된 개별 기록은 제외하고 정상 기록은 유지합니다. JSON 배열 전체가 손상되면 오류 상태를 표시합니다.

현재 PB-05의 저장 버튼은 안전 결과에만 있고 최근 50건을 보관합니다. PB-06은 그 저장 기능을 읽는 UI입니다.
모든 완료 결과의 자동 저장, 입력 유형 전달, 원문/근거를 포함하는 전체 상세 데이터, BE 검사 기록 API는 별도 연동 사항입니다.
이미지의 회원 전용/90일 보관/암호화 문구는 현재 구현으로 보장할 수 없어 실제 기능에 맞는 로컬 보관 안내로 대체했습니다.
하단에는 연결 가능한 홈/검사 기록만 제공하며, 미구현 설정/안전 가이드 메뉴는 추가하지 않았습니다.

## 원본 PB-06 커밋의 검증 기록

아래 항목은 `e9ec1f2` 작성 당시 문서에 기록된 결과이며, 최신 `origin/dev`와 통합한 작업의 검증 결과는 아닙니다.

- Debug APK assembleDebug 성공.
- main 소스의 compileReleaseKotlin 성공.
- PB-06 저장/필터 4개, 화면 6개(한글 검색/쉬운 위험 카드 포함), 통합 Manifest 2개 테스트 통과.
- 기존 IntegratedManifestTest의 nullable requestedPermissions 컴파일 오류를 orEmpty()로 수정하고 PB-06 Activity 등록 검증 추가.
- Android 에뮬레이터에서 샘플 목록/상세, 쉬운 모드, 실제 빈 상태 렌더링 확인.

## 아직 보장하지 않는 항목

- 실제 API에서 기록을 가져오거나 모든 분석 결과를 자동으로 저장하지 않습니다.
- 이 저장소는 별도 암호화 저장소가 아닙니다. 회원 인증/암호화/90일 만료 정책은 이 UI 변경에 포함되지 않습니다.
- 실제 기기별 접근성, 매우 큰 글꼴 및 다양한 해상도는 추가 QA가 필요합니다.

## 에뮬레이터 한글 입력 설정 수정

영어만 등록된 Gboard에 한국어 두벌식을 추가하고 현재 언어로 선택했습니다.
물리 키보드 연결 시 화면 키보드 표시(show_ime_with_hard_keyboard=1)를 켰습니다.
일반 입력 대신 Gboard의 필기 툴바/스타일러스 연습 창이 표시되는 문제는 에뮬레이터의 자동 필기(stylus_handwriting_enabled=0)를 꺼 해결했습니다.
이 설정은 현재 에뮬레이터에 적용되며 APK가 다른 기기의 키보드 언어를 강제로 변경하지 않습니다.

## 최신 디자인 dev 통합

- 날짜별 흰색 그룹 카드, 상태 아이콘·배지, 검색/삭제 도구, 독립 분석 점수 막대와 상세 목록 복귀 버튼을 적용했습니다.
- 쉬운 모드는 Easy History 상단, 개인정보 안내, 상태별 별도 카드와 원형 화살표, 기본 모드 전환 버튼을 사용합니다.
- 기본 화면의 하단은 dev의 HomeBottomNavigation을 유지합니다. 쉬운 모드의 홈/설정과 상단 프로필도 기존 HomeDestination 콜백으로 연결합니다.
- dev의 initialRecordId/onCloseDetail을 유지해 홈의 최근 검사에서 해당 기록 상세로 직접 진입하고 홈으로 돌아올 수 있습니다.
- PHONE 및 UNKNOWN 유형과 판정 미확정을 유지합니다. 쉬운 필터에 전화번호 및 기타 검사도 표시해 기존 기록이 누락되지 않게 합니다.
- aiLikelihood는 선택적 메타데이터로 저장·복원하며 명시적인 HIGH 분류에만 AI 생성 의심 배지를 사용합니다. 점수로 등급을 새로 계산하지 않습니다.
- 저장소 키와 최근 50건 보관, 중복 ID 갱신, 삭제 확인창과 원문·링크·근거 미보관 정책을 유지합니다.
- HistoryRoute가 다시 활성화되면 목록을 갱신합니다. 샘플 목록과 쉬운 모드는 기존 debug 소스의 Preview에서 확인할 수 있습니다.
- 통합 검증: Debug APK 빌드 및 Release Kotlin 컴파일 성공. 실제 에뮬레이터의 결과/뒤로 가기/홈 복귀/기록 상세/필터/삭제 확인/큰 글씨/HTTP 오류 및 재시도 테스트 15개 통과.
- JVM 검증에는 기존 AnalysisFlowScreenTest.errorsShowDistinctMessagesAndSafeHttpStatus의 HTTP 문구 표시 실패가 남습니다. 해당 오류 팝업 소스와 테스트 메서드는 원본을 유지했으며, 동일한 HTTP 503 표시와 재시도는 실제 에뮬레이터 테스트에서 통과했습니다. 전체 테스트 통과를 의미하지 않습니다.
