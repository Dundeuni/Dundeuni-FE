# PB-09 인증 화면 디자인 대조

기준: 2026-10-30, `feature/17-auth-ui-sprint3`.

## 자료와 한계

- 로그인은 이번 대화에서 받은 디자인 정보와 스크린샷을 사용했다. 나머지 화면은 2026-10-30 사용자가 전달한 PNG 11장(약관 1, 회원가입 이메일 4, 가입 정보 3, 재설정 2, 가입 완료 1)을 기준으로 대조했다.
- 전날 Figma 호출 한도로 보류했던 대조는 첨부 PNG를 기준으로 재개했다. Figma 노드 ID는 화면 식별용이며 PNG 확인을 Figma 최신 파일 전체 검증으로 확대하지 않는다.
- 첨부 이미지를 앱 배경으로 사용하지 않고 기존 Compose UI와 에셋을 재사용했다. 누락된 완료 플랜·설정 아이콘은 로컬 VectorDrawable로 보완했다. 별도 SVG 원본과 바이트 단위로 동일한 에셋이라는 뜻은 아니다.
- 실제 앱 화면은 API 36 에뮬레이터에서 기존 상태 캡처 테스트로 다시 생성했다. 화면보다 긴 콘텐츠는 스크롤해서 확인한다.

## 로그인 에셋 확인

기존 파일을 재사용했으며 새 이미지를 그리거나 디자인 스크린샷을 앱 배경으로 넣지 않았다. 브랜드는 원본 이미지의 두 프레임 자르기 방식을 유지한다.

## 2026-10-29 검증 기록

### 2026-10-30 실제 로그인 진입 경로 보완

- 사용자 확인에서 홈 → My 쉼터 → 로그인 → 회원가입 → 이메일 인증으로 진입하면 API 미연결 안내가 표시됐다.
- 기존 인증 흐름 테스트는 LoginPreviewActivity를 통해 진입해 실제 LoginActivity의 샘플 모드 전달 누락을 검출하지 못했다.
- LoginActivity에서 약관 화면으로 이동할 때 Debug 앱에만 EXTRA_DEMO를 전달하도록 수정했다. Release는 false이며 이메일·가입 단계에서도 BuildConfig.DEBUG를 확인한다.
- 실제 홈 진입부터 샘플 번호 발송·인증·가입 완료·홈 복귀까지 검증하는 회귀 테스트를 추가했다. 완료 후 로그인 세션이 생성되지 않는지도 확인한다.
- 기존에 열린 이메일 화면은 이전 Intent 값을 유지하므로 로그인까지 돌아가 회원가입으로 다시 진입해야 한다. 샘플 번호는 123456이다.
