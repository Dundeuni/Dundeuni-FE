# PB-09 Sprint 3 비밀번호 재설정 UI

이슈 #17의 비밀번호 재설정 UI와 로그인 진입 연결이다. 실제 메일 발송·인증·비밀번호 변경 API는 연결하지 않는다.

## 확인 방법

1. Debug 앱의 로그인 화면에서 `비밀번호 재설정`을 누른다. 기존 로그인 UI 미리보기에서도 같은 화면을 연다.
2. 이메일 형식 오류와 필드 지우기를 확인한 뒤 `example@kau.kr`로 인증번호를 요청한다.
3. 화면에 표시된 샘플 번호 `123456`을 입력한다. 다른 번호는 불일치 오류를 표시한다.
4. `새 번호 발송`으로 번호 입력·오류·3분 타이머가 초기화되는지 확인한다. 이메일을 바꾸면 이전 인증은 무효화된다.
5. 인증 후 새 비밀번호와 확인 값을 입력한다. 기존 회원가입의 8~20자·영문/숫자 조합 규칙을 재사용하며 특수문자는 보안 강도 표시에 사용한다. BE 확정 정책으로 교체할 수 있다.
6. 일치 여부·보기/가리기·제출 중 비활성 상태를 확인한다. 샘플 완료 안내에서 로그인으로 돌아간다.
7. 새 비밀번호 화면에서 뒤로 가면 입력과 임시 인증값을 지우고 이메일 인증부터 다시 시작한다.

Debug 화면에는 `UI 미리보기 · 샘플 인증`, 실제 발송·변경이 없다는 안내를 표시한다. 이 흐름은 로그인 세션을 만들거나 변경하지 않는다. Release는 미연결 Gateway를 사용하므로 임의의 번호를 인증 성공으로 처리하지 않는다.

## 구성 및 API 연결 지점

- `PasswordResetActivity`: 로그인에서 진입하는 내부 Activity. 이메일 인증과 새 비밀번호 화면을 연결한다.
- `EmailVerificationScreen`: `passwordReset` 모드에서 재설정 제목·설명·재발송 표시를 사용한다. 회원가입은 기존 모드를 유지한다.
- `EmailVerificationViewModel`: 기존 타이머·재발송·만료·중복 요청 처리를 재사용한다. 재설정 성공은 `VerifiedForReset(grant)`로 구분한다.
- `PasswordResetGateway`: 발송·인증·비밀번호 변경의 주입 경계다. HTTP 엔드포인트나 BE 토큰 계약을 정의한 것은 아니다.
- `PasswordResetViewModel`: 이메일 인증에서 받은 임시 확인값이 있어야 제출한다. 인증 만료 시 비밀번호를 지우고 재인증을 요구한다. 뒤로 가기 시 진행 중 제출을 취소하며 늦은 결과로 화면을 다시 열지 않는다.
- `PreviewPasswordResetGateway`: Debug 전용 샘플 구현. 3분 유효시간과 일회용 임시 확인값을 사용하며 네트워크 호출을 하지 않는다.
- 비밀번호와 임시 확인값은 ViewModel 메모리에만 둔다. Intent·SavedStateHandle·SharedPreferences·로그에는 넣지 않는다. 완료·재인증 시 지운다.
- Activity 회전 시 상태를 유지한다. 프로세스가 다시 만들어지면 인증부터 다시 진행한다.

## BE와 확인할 항목

- 재설정 인증 요청·확인·변경 API 및 인증 목적 구분
- 이메일 미가입·번호 불일치·만료·재발송 제한·네트워크 오류 응답
- 번호 유효시간과 인증 완료 후 변경 권한의 유효시간·일회성
- 비밀번호 규칙 및 이전 비밀번호 재사용 금지 여부
- 변경 후 기존 로그인 세션·다른 기기 로그아웃 정책

BE 확인 전에는 이전 비밀번호 금지나 다른 기기 자동 로그아웃을 실제 동작으로 안내하지 않는다. Figma의 해당 문구는 샘플 동작 안내로 대체했다. 완료 전용 디자인이 없어 기존 인증 UI의 AlertDialog로 샘플 완료와 로그인 복귀를 구성했다.

## 검증

- `PasswordResetViewModelTest`: 인증값 없는 제출·불일치·중복 제출·성공 후 비밀번호 제거·실패·만료·취소·이메일 변경 시 인증값 무효화를 확인한다.
- `PasswordResetFlowQaTest`: 로그인 진입·번호 오류·재발송·비밀번호 오류 수정·완료·로그인 복귀·회전·키보드 위 제출을 확인한다.
- 기존 회원가입·세션·로그인 수명주기 테스트를 함께 실행한다.
- 진단 캡처는 저장소 외부의 `E:\든든이\FE\PB09-sprint3-QA-2026-10-29`에 보관한다.

Windows 테스트 실행기의 `java.library.path` 인용 오류를 피하기 위해 이번 검증 명령의 PATH에 있는 따옴표만 제거했다. 시스템 PATH는 변경하지 않았다. 기존 Release 중간 파일이 잠겨 있어 Release 빌드는 임시 출력 경로에서 수행한다.
